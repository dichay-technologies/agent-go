# Управляемая память, чат-режим и межагентная шина

---

## 1. Рабочая память агента (`MemoryBank`)

`MemoryBank` (`memory.go`) — потокобезопасное JSON-сериализуемое хранилище, разделённое на три области, которыми могут управлять **и хост-код на Go, и сам агент через встроенные инструменты**.

### А. Ключ-значение: факты, настройки и артефакты (`MemoryEntry`)
- **Из Go:**
  - `bank.Set(key, value, tags...)` — сохранить или обновить запись;
  - `bank.SetPinned(key, value, true, tags...)` — закрепить запись (защищена от внешней перезаписи при импорте памяти от других агентов);
  - `bank.Get(key)` / `bank.Value(key)` / `bank.Entries(tagFilter...)` / `bank.Delete(key)`;
  - `bank.CopyTo(otherBank, keys...)` — передать выбранные (или все) ключи памяти другому агенту.
- **Инструменты самого агента (`MemoryTools()`):**
  - `memory_set`, `memory_get`, `memory_delete`.

### Б. Управляемый буфер диалога — «чат» (`ChatEntry`)
В отличие от простого массива сообщений, каждая реплика в `MemoryBank` имеет собственный `ID` (`m_1`, `m_2`, ...), флаг закрепления `Pinned` и признак сводки `Summary`.
- **Из Go:**
  - `bank.AppendChat(role, content)` и `bank.AppendMessage(msg, pinned)`;
  - `bank.PinMessage(id, true)` — закреплённые правила пользователя никогда не удаляются при сжатии и автоочистке;
  - `bank.EditMessage(id, newContent)` и `bank.DeleteMessages(ids...)`;
  - `bank.CompactChat(summary, keepLast)` — заменяет старые незакреплённые реплики единой компактной сводкой `[Chat Summary]`, сохраняя все `Pinned`-сообщения и `keepLast` последних сообщений;
  - `bank.SetMaxChatMessages(limit)` — автоматическое скользящее окно;
  - `bank.ClearChat(keepPinned)`.
- **Инструменты самого агента (`ChatTools()`):**
  - `chat_inspect` — просмотреть список реплик чата с их `ID`, ролями и оценкой размера в токенах;
  - `chat_pin` — закрепить или открепить важную реплику;
  - `chat_manage` — сжать историю диалога в `summary` (оставив `keep_last` свежих реплик) или удалить шумные сообщения по `delete_ids`;
  - `chat_clear` — очистить диалог с сохранением закреплённых инструкций.

### В. Собственный список задач (`TaskItem`)
- **Из Go:** `bank.AddTask(...)`, `bank.UpdateTask(id, status, notes, assignee)`, `bank.DeleteTask(id)`, `bank.Tasks(statusFilter...)`.
- **Инструменты самого агента (`TaskTools()`):**
  - `task_add` — добавить задачу со статусом `pending`; если передать `"add_to_plan": true`, задача одновременно добавляется как живой узел `PlanStep` в текущий граф исполнения `Scheduler`;
  - `task_update` — сменить статус (`pending`, `in_progress`, `done`, `blocked`, `skipped`), исполнителя или заметки;
  - `task_list` — получить список задач с фильтрацией по статусу.

Подключить весь набор инструментов самоуправления сразу можно одной опцией **`WithWorkspaceTools[S]()`**.

## 2. Диалоговый режим (`ag.Chat` и `ag.StreamChat`)

Любой агент `AI[S]` поддерживает полноценный чат-режим без мутации своей конфигурации:

```go
// Синхронный ход диалога:
reply, err := coord.Chat(ctx, "Запомни FPS=60 и запланируй монтаж интро")

// Потоковый ход диалога (SSE-стриминг дельт текста в реальном времени):
for delta, err := range coord.StreamChat(ctx, "Сделай сцену 3 динамичнее") {
    if err != nil {
        log.Fatal(err)
    }
    fmt.Print(delta)
}
```

На каждом ходу `Chat` / `StreamChat` автоматически:
1. Добавляет сообщение пользователя в `MemoryBank`.
2. Оставляет `SystemPrefix` неизменным для провайдерского KV-кеша, а факты/задачи из `MemoryBank`, входящие события из `Bus` и историю `ChatMessages()` передаёт в сообщениях запроса.
3. Записывает итоговый ответ ассистента обратно в `MemoryBank`.

## 3. Межагентная шина (`Bus`), пересылка памяти и `Tell`

`Bus` (`bus.go`) объединяет координатора, субагентов и хост-приложение в общую сеть обмена сообщениями `Envelope`:

- **Автоматическое наследование:** при `Fork` и `SpawnAsync` дочерние агенты автоматически подключаются к `Bus` родителя и регистрируют свои `ID` и `MemoryBank`.
- **Отправка и получение между агентами (`BusTools()`):**
  - `agent_send` — отправка сообщения по `ID` агента, родителю (`"to": "parent"`) или широковещательно всем (`"to": "*"`). Если указать `"share_memory_keys": ["fps", "beats"]`, перечисленные записи из `MemoryBank` отправителя автоматически копируются в `MemoryBank` получателя (не перезаписывая его `Pinned`-записи).
  - `agent_recv` — чтение входящих сообщений из почтового ящика (мгновенно или с блокирующим ожиданием ответа до `wait_ms` мс).
  - `agent_peers` — обнаружение всех активных агентов на шине и `ID` родителя.
- **Внешние сигналы от пользователя / UI (`ag.Tell`):**
  Вызов `ag.Tell("editor-ui", "Сцена 2 заблокирована")` кладёт событие в почтовый ящик агента. На следующем шаге оно автоматически вычитывается в `RunState.PendingEvents` и подаётся в контекст модели.
- **Реактивные подписки (`bus.Subscribe`):**
  `unsub := bus.Subscribe("*", func(env agentgo.Envelope) { ... })` позволяет логировать или транслировать все сообщения между агентами в WebSocket/SSE.
